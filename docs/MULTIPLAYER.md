# Мультиплеер

## Модель

- **Хост** (первый вошедший в комнату) считает физику в реальном времени и
  10 раз в секунду рассылает снапшоты.
- **Гости** шлют команды (`cmd`) и применяют полученные снапшоты к приборам.
- Код комнаты — 4 символа (генерируется у хоста), до 8 игроков.
- При выходе хоста комната закрывается: гостям приходит `host_left`, они возвращаются в меню.

Задержка гостя ≈ RTT до релея + 50–100 мс. Для симулятора щита этого достаточно: приборы
плавно интерполируются, а команды — дискретные события.

wss://npp-relay.tgargach12.workers.dev/ws

Адрес прописан по умолчанию в `Assets/Resources/server.json`; health-check:

## Облачный релей (Cloudflare) — свой экземпляр

Папка `server/worker`. Нужны Node.js и аккаунт Cloudflare.

```bash
cd server/worker
npm install
export CLOUDFLARE_API_TOKEN=...      # токен с правами Workers Scripts:Edit, Durable Objects:Edit
export CLOUDFLARE_ACCOUNT_ID=...
npx wrangler deploy
```

В выводе будет адрес вида:

```
https://npp-relay.<ваш-поддомен>.workers.dev
```

Адрес WebSocket — тот же хост с путём `/ws`:

```
wss://npp-relay.<поддомен>.workers.dev/ws?room=K7Q2
```

Проверка: `curl https://<адрес>/health` → `{"ok":true,...}`.

Адрес по умолчанию для игры задаётся в
`unity/NPPControlRoom/Assets/Resources/server.json`:

```json
{ "url": "wss://npp-relay.<поддомен>.workers.dev/ws" }
```

Игрок может переопределить адрес в *Настройках* (сохраняется в `PlayerPrefs`,
поле «Адрес сервера»).

### Как устроено

- Worker маршрутизирует `/ws?room=CODE` в Durable Object комнаты.
- Используется WebSocket Hibernation API (`state.acceptWebSocket`) — DO «спит» между
  сообщениями, расходы минимальны.
- Роли назначаются в DO: первый `join` становится хостом.
- Сообщения `cmd` доставляются только хосту; `state` — только гостям.

### Ограничения free-плана

- 100 000 запросов/сутки, Durable Objects на SQLite — бесплатно в рамках лимитов.
- Нет аутентификации: кто знает код комнаты, тот может войти. Коды короткоживущие.

## LAN-релей (без интернета)

```bash
cd server/node-relay
npm install
npm start
```

Сервер слушает `0.0.0.0:8787`, печатает LAN-адрес. В игре у всех участников:
*Настройки → Адрес сервера* → `ws://192.168.x.x:8787/ws`.

Разрешите порт 8787 в брандмауэре Windows у хоста релея.

## Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| «Не удалось подключиться» | нет сети до релея / неверный URL | проверьте `/health`, `wss://` для облака, `ws://` для LAN |
| «Сервер не подтвердил вход» | комната заполнена / старый воркер | обновите воркер, повторите |
| Низкий ping, но команды «залипают» | хост на слабом ПК | уменьшите качество графики, закройте фоновые задачи |
| «Хост покинул игру» | закрылся клиент хоста | создать новую комнату |
| Чат не работает | не в комнате | сообщения доступны только в мультиплеере |

## Расширение протокола

Сервер — чистый релей, вся логика игры на клиенте. Чтобы добавить тип сообщения:

1. добавьте `case` в `webSocketMessage` воркера и `server.js` (правило: `cmd` — только хосту,
   `state` — только гостям, остальное можно broadcast);
2. обработайте тип в `NetworkSession.Handle` (Unity, `Assets/Scripts/Net/NetworkSession.cs`).

Проверить релей без Unity можно скриптом `tools/relay-smoke.js` (см. tools/).
